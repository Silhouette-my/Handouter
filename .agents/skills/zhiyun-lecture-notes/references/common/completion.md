# Common · Completion and self-check

Before claiming completion:

1. Confirm every output listed in `expected_outputs` exists and is non-empty.
2. Confirm the entire requested course range was actually processed; do not infer completeness from reading only the beginning/end.
3. Recheck numbers, formulas, negations, conditions, teacher self-corrections, and formal course requirements against source evidence.
4. Confirm no unrelated old-course content, unsupported biography/grading claims, credentials, signed URLs, or private data leaked into outputs.
5. Confirm PPT usage matches the selected slide module and image links are valid when embedding is enabled.
6. If only part of the material was processed, say so explicitly instead of claiming a complete lecture.
7. Except for summary, compare the body against the actual lecture sequence; do not move course requirements or merge distant passages into a new logical outline.
8. Check the beginning for an always-visible assessment callout whenever supported requirements occur anywhere in the lecture. Include homework, quizzes, exams, group work and grading rules, preserving final corrections and uncertainty.
9. Confirm course information is inside a closed HTML details fold, and each main chapter has one shared `本章时间与来源` fold after its heading. Do not add separate folds for natural paragraphs, list items, table rows or subsections. Check real intervals against evidence, separate disjoint ranges, and mark unknown timing rather than guessing; invisible comments cannot replace the chapter fold.
10. Put the final unresolved checklist in one closed `待核对` details block, with its evidence inside; omit it when empty. Keep actionable assessment uncertainties visible in the upfront important callout as well.

The final chat/status response should be short: report output paths, coverage status, unresolved-item count, and whether external supplements were used. Do not duplicate that execution report inside the notes unless it is reader-relevant.
