# Execution · multi-output

Several deliverables share the same evidence, but each output is a separate writing task.

- Read and understand the course evidence once, then plan each selected mode independently.
- Write every path listed in `expected_outputs`; do not merge different modes into one Markdown.
- Do not let one mode's constraints contaminate another: summary compression must not shorten deep notes; verbatim's closeness to classroom wording must not make full retain oral redundancy; full's de-oralization must not over-compress verbatim.
- summary's thematic order must not reorder verbatim/full/deep. All outputs share the upfront assessment callout, folded course information, one timing fold per chapter and the final unresolved-check fold; preserve each mode's depth and wording separately.
- Reuse verified terminology/facts across outputs, but perform a separate mode-specific self-check for each file.
- A multi-output task is complete only when all requested output files exist.
